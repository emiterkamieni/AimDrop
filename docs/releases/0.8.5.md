# AimDrop 0.8.5

**Build 25**

## Receiver visibility on other devices

- AimDrop automatically stays out of the system AirDrop picker on the Mac running
  it, while remaining discoverable by nearby sending devices over AWDL. No extra
  setting is needed.
- External, AWDL-only mDNS advertisements replace the two AirDrop pairing service
  registrations. The internal HTTP3 broker keeps its existing registration and
  transport path.
- Discovery recovers automatically when AWDL disappears, its address changes, an
  advertisement cannot be sent, or the Mac wakes.
- **Waiting for Wi-Fi…** and **Restoring receiver visibility…** describe temporary
  discovery interruptions. Both statuses are localized in all 15 languages.
- **Unsaved transfers** stays usable while discovery is unavailable, so you can
  still save received files or move them to Trash.

## Upgrade without resetting your receiver

- Stored pairing, receiver name, avatar, settings and inbox files are preserved.
- Upgrading alone does **not** require a new PIN. Changing the receiver name or
  avatar still requires new pairing.
- **0.8.4 users:** choose **Check for Updates… → Update and Restart** in AimDrop.
  This release increases the internal build number from 24 to **25**.
- The local 0.8.3 build also supports in-app installation. **0.8.4 remains the
  first public release with the built-in installer.** Users of public 0.8.2 or
  earlier must install a current release manually once.

## Installation and compatibility

- Requires an **Apple Silicon Mac with macOS 26 or later**. Python is bundled.
- The release archive and update feed carry **Ed25519 signatures** for the in-app
  updater. The app itself remains ad-hoc signed; a first manual installation may
  require **System Settings → Privacy & Security → Open Anyway**.
- Download **AimDrop-0.8.5-macos-arm64.zip** and verify it with **SHA256SUMS**.
  The attached **appcast.xml** is the signed feed used by the updater. End users
  do not need the publisher's signing key or Keychain signing dialogs.

## Validation status

The physical prototype completed iPhone PIN pairing and a **179,825,441-byte
upload with HTTP 200**, leaving **one durable inbox file**. The user also confirmed
that the receiver was absent from the receiving Mac's own system AirDrop.

The final release's native helpers and Python receiver were then tested
byte-for-byte in an isolated signed app using the production
**app → Python → native helper** launch chain. Two further iPhone uploads
(4,151,124 bytes each) completed with HTTP 200, without another PIN. The pairing
store stayed byte-identical and the local observer found no recipient services.

Automated checks passed: 132 Python tests, DNS packet/lifecycle and recovery
checks, native PIN/PairVerify/HTTP3 and durable-inbox checks, update draining,
discovery-status/inbox UI, localization and updater checks.

Second-Mac interoperability and physical sleep/Wi-Fi cycling remain manual
follow-up checks; interface loss, address/index changes, wake gaps and socket
failures are covered by the offline lifecycle tests.
