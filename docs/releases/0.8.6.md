# AimDrop 0.8.6 — pairing fixes

Local validation build 26; publication pending.

- Fixes pairing with Macs whose native contact photo exceeds 512 KiB. The PIN
  could authenticate successfully, but AimDrop rejected the sender's identity
  afterward, causing macOS to reset the PIN entry dialog. Peer photos are not
  used or stored by AimDrop and no longer inherit the outgoing avatar limit.
- The PIN window now uses the receiver's original credential deadline. A retry
  does not restart the display timer. Expiry closes the window silently, also
  during menu tracking and after wake; stale events cannot reopen it.
- Local builds refresh the application bundle's modification date in Finder.

Existing pairing, receiver name/avatar, preferences and inbox data are preserved.

## Validation status

- Reproduced the Mac pairing failure against the previous receiver using a
  synthetic 551,006-byte peer contact image; the corrected receiver accepts it.
- The same native macOS identities that failed enrollment before the fix now
  pass. Diagnostic inspection used field sizes only.
- Passed 134 Python tests, PIN-window and updater UI checks, persistent pairing
  and PairVerify checks, and bundled native PIN/HTTP3/inbox/lifecycle checks.
- Verified the portable bundle, signatures, ZIP contents and checksum.

The physical two-Mac retry with this build remains pending. Details of the
confirmed cause and regression checks: [Mac PIN reset](../research/mac-pin-reset.md).
